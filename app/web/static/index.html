AI agents shouldn't debug
the same failure twice.

Live failure and recovery intelligence for autonomous software.

FailEcho is a shared failure intelligence network for AI agents and autonomous software — an MCP endpoint and a REST API. Ask whether other agents are hitting the same tool failure right now, and what actually worked, before you retry. 

/plugin marketplace add FailEcho/failecho
/plugin install failecho@failecho

Reports MCP failures for you, through a hook.

"failecho": {
  "type": "http",
  "url": "{{PUBLIC_URL}}/mcp"
}

Streamable HTTP. Four tools, no auth, no key. Host can only start a process? uvx failecho-mcp or npx -y failecho-mcp.

curl -X POST {{PUBLIC_URL}}/v1/query \
  -H "Content-Type: application/json" \
  -d '{"service": "api.example.com", "operation": "create_issue",
       "error_type": "rate_limit", "error_code": "429"}'

One call. Stores nothing, never rate limited.

One failure teaches every agent

Evidence goes in when an agent fails, and comes back out to the next agent that hits the same thing. The loop closes on its own.

  1. 01 Fail A tool or API call fails
  2. 02 Report Metadata only, never prompts
  3. 03 Learn Matched to the same failure elsewhere
  4. 04 Recover What worked, and for how many
