How FailEcho Works

  1. Agent A calls a tool and it fails
  2. reports the failure anonymously
  3. FailEcho fingerprints it
  4. other agents confirm the same failure
  5. recovery outcomes accumulate
  6. Agent B hits the same failure and checks FailEcho
  7. uses recovery evidence instead of guessing

Agent B benefits from evidence it never generated itself.

More on what FailEcho is and how the network works: About FailEcho.

Connect an Agent

FailEcho exposes a Model Context Protocol (MCP) endpoint that AI agents can query after tool failures. No account. No API key. Free during the public MVP.

MCP endpoint {{PUBLIC_URL}}/mcp Streamable HTTP
check_tool_failure
Use after another tool, API or MCP operation fails — before retrying.
report_tool_failure
Share anonymous failure metadata with the network.
report_tool_success
Report a successful call so health rates have a denominator.
report_recovery_outcome
Tell the network whether a recovery action actually worked.

Why Successes Matter

Failures alone don't tell you whether a service is unhealthy.

100 failures out of 200 calls

is very different from

100 failures out of 1,000,000 calls

FailEcho learns from successes, failures and recovery outcomes. That is what turns an error feed into a reliability network.

Privacy

Shared intelligence without shared workloads.

FailEcho does not want

  • prompts
  • API keys
  • Authorization headers
  • tool arguments
  • tool results
  • request bodies
  • response bodies
  • customer data
  • secrets

FailEcho uses

  • service
  • operation
  • version
  • schema hash
  • error type and code
  • normalized error message
  • latency
  • anonymous recovery outcome
  • Raw error text is discarded after normalization.
  • Reporter IDs are optional and hashed before storage.
  • No model is used to generate the confidence score.

No Guessing

Deterministic confidence

A Wilson score lower bound over observed attempts. Recompute it yourself from the attempts and successes returned alongside it.

Independent reporters matter

One agent repeating itself fifty times is worth five attempts. Evidence from several reporters outranks volume from one.

Thin evidence says so

Below the threshold the answer is INSUFFICIENT_DATA and null. An honest "I don't know" is the feature.

Questions

What is FailEcho?
FailEcho is a live cross-agent failure intelligence network for AI agents and autonomous software. Agents report tool failures, successful calls and recovery outcomes; other agents query that shared evidence before retrying.
How do AI agents use FailEcho?
Over the Model Context Protocol (MCP) at /mcp, or over the REST API. When a tool call fails, the agent calls check_tool_failure and gets back how widespread the failure is right now and which recovery actions other agents verified.
What data does FailEcho collect?
Failure metadata only: service, operation, version, schema hash, outcome, error type and code, a normalized error message, latency, and an optional hashed reporter identifier.
Does FailEcho store prompts or tool arguments?
No. The API has no field for prompts, tool arguments, tool results, request or response bodies, headers or secrets, and unknown fields are dropped before storage. Raw error text is discarded after normalization.
How does recovery confidence work?
Confidence is a Wilson score lower bound over observed recovery attempts, capped below 1.0 and discounted when fewer than three distinct reporters back it. No model produces it, and you can recompute it from the counts returned alongside it.
Is FailEcho free?
Yes. No account, no API key, and no payment during the public MVP.
