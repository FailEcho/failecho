# Outside review, 20 September 2026

An outside model reviewed the checkout at `a7756bc`, read the published
packages against it, ran the suite (221 tests, all passing) and queried
production read-only. Its verdict: *"a useful experimental component for teams
running repeatable API workflows, especially with their own recovery history.
The public network is not yet a proven benefit for ordinary agent builders."*
It found no fabricated numbers; it found claims that say more than the
measurements support, and real defects. That is the most useful thing anyone
has done for this project, and the findings are kept here in full, with what
was done about each.

## Fixed the same day (`381119c`..`HEAD`)

1. **A 5xx with the word "invalid" was filed as a validation error.**
   `503 invalid upstream response` matched the validation rule first and was
   stored as `validation_error/503`, splitting it from every other 503 on that
   service. `server_error` now precedes `validation_error` in all three copies
   of the table (wrapper, Claude Code hook, scanner) and in the Node proxy, with
   a test that keeps the four in step.

2. **The advice line hid what the server qualified it with.** A decaying
   recommendation read as solid: *"try retry, worked 100/105 (confidence
   0.89)"* while its recent attempts were failing. The line now carries the
   decay flag, the server's warning, the pooling scope, and whether the
   evidence is the caller's own history, in both languages:

       FailEcho: try retry, worked 100/105 (evidence score 0.89) -- recent
       attempts are failing; evidence pooled across this service; your own
       history only.

   "Confidence" is renamed **evidence score** everywhere it is shown: it is a
   lower bound over observed attempts, not the probability that this caller
   recovers.

3. **The proxy could send error text.** It inherited `FAILECHO_SEND_ERRORS`
   from the environment, against its own unconditional promise. That switch is
   the wrapper's, for code whose errors the author owns; through the proxy the
   text belongs to somebody else's tool. The proxy now forces it off, with a
   test that sets the variable and checks nothing but the shape leaves.

4. **"Stores nothing" was too strong for a query.** A query writes no
   observation and keeps no record of the question, but it does add 1 to a
   daily counter of answered/unanswered queries. Every place that said "stores
   nothing" about a read now says exactly that (front page copy, llms.txt,
   /setup, /network).

5. **Two metric names claimed more than they measured.**
   - "tasks completed" is now **"runs marked completed (see grading)"**, and
     the lab scoreboard states the grading rule in plain words: a model run
     counts when it returned an answer rather than a failure marker; a builder
     or OpenCode run when the requested file exists and matches the task's
     pattern. A wrong but well-formed answer counts. The per-call recovery and
     retry rows are the harder evidence.
   - "pointless retries avoided" is now **"retries the network said to skip"**.
     It counts skips, not verified counterfactual failures; the lab itself
     recorded a blind GitHub retry that succeeded where askers were told to
     skip.

## Accepted, not yet done

6. **Grade deliverables, not shapes.** Check the produced artefact against an
   independent check (correct versions, correct star counts), and report
   successful API recovery, valid output, partial and correct completion
   separately. High impact, medium effort; the honest interim is the grading
   note above.

7. **A stronger control.** Today's control is one retry after 3 s, so the
   comparison shows value over a weak policy, not over competent local recovery
   (a fallback table, `Retry-After`, a circuit breaker). Wanted: blind retry vs
   strong local recovery vs local recovery plus FailEcho, paired by
   task/model/time, reported both including and excluding infrastructure
   failures. Until then, no claim of generalizable uplift.

8. **Inferred recovery is correlation.** The HTTP inference keys on method,
   host and first path segment, so two different searches share a key, and a
   later success can be credited to an earlier failure; elapsed time becomes
   "backoff" with nobody having waited on purpose. The MCP proxy's argument
   hash is tighter but still cannot see credentials, routing or external state.
   Wanted: inferred outcomes stored and weighted apart from explicitly reported
   ones.

9. **Reporter ids are not independence.** Ids are self-chosen and a restart
   mints a new one, so "unique reporters" counts processes, not independent
   operators; pooled recommendations attach provenance for the exact
   fingerprint rather than for every contributing one. Wanted: separate
   installation, operator, anonymous and verified-contributor evidence, and
   provenance on the evidence actually used. Poisoning resistance is untested.

10. **Matching trades missed evidence for loose pooling.** Fingerprints include
    version, schema and normalized text; service-level pooling ignores all
    three, so an auth error can travel between operations whose permissions
    differ. Wanted: explicit matching levels -- exact, compatible, service-wide
    -- with progressively weaker recommendations.

11. **Privacy guarantees need the narrower contract.** The defaults are sound,
    but the automatic HTTP mode turns a URL into host plus first path segment,
    which can itself be an identifier, and normalization keeps ordinary
    sentences. Wanted: approved service names and route templates, private
    hosts excluded by default, a payload preview, and FAQ wording that matches
    the qualification the about page already makes.

12. **Proxy bounds and wording.** Byte-for-byte forwarding is true of the stdio
    path, which is what the tests cover; the remote HTTP path parses and
    re-serialises, and omits server-initiated GET streams and OAuth. The 3 s
    advice budget is a socket timeout, not an end-to-end deadline. Wanted: a
    real deadline, bounded queues, and a compatibility matrix.

13. **Supply chain.** A proxy sits in the tool path and can inherit
    credentials. Wanted: pinned install examples, artifact hashes, lockfiles,
    release provenance and an update policy.

14. **Cold start is the central limitation** and the launch should say so
    beside the lab results, leading with "experimental recovery evidence
    delivered inside tool errors, with optional sharing and self-hosting".

## Never to claim, on this evidence

Proven general task-completion uplift; guaranteed exclusion of secrets;
verified independent consensus; universal MCP transparency; a guaranteed three
second ceiling.
